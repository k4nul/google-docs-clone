- 현재 런타임 기본값은 여전히 단일 프로세스 owner 판정이지만, `ROOM_LOCATOR=sqlite` / `ROOM_COORDINATOR=sqlite`와 `SNAPSHOT_STORE=sqlite`를 같은 shared SQLite DB 경로 집합으로 맞추면 lock-capable storage 범위에서는 snapshot durability와 authoritative lease CAS를 함께 사용할 수 있다. 이제 `SNAPSHOT_STORE=flash_kv|simple_db|docdb|shorterdb|heed|hightower_kv|jammdb|fjall|persy|persistent_kv|native_db|nikidb|nodb|parity_db|pickledb|microkv|redb|rskey|readb|rustlite|canopydb|ckydb|scdb|surrealkv|sled|rustbreak|yedb|btree_store|siamesedb|structsy|abyssiniandb|aeternusdb|thunderdb|dblite|dbless|sanakirja|snaildb|tinykv|saberdb|jsondb`로 embedded database durability를 선택할 수도 있고, `SNAPSHOT_STORE=s3`로 object storage durability를 선택할 수도 있으며, `ROOM_LOCATOR=managed` / `ROOM_COORDINATOR=managed`를 external lease service에 연결하고 `SNAPSHOT_STORE=managed`를 external snapshot service에 연결하면 ownership coordination plane과 snapshot durability plane을 모두 shared SQLite DB 밖으로도 분리할 수 있다. `static` owner hints와 `file` lease state는 계속 best-effort 준비 경계로 유지된다.
- lease/heartbeat 갱신 정책과 외부 coordination 저장소 계약은 `README.md`, `docs/architecture.md`, `docs/setup.md`, `docs/api.md`, `docs/conventions.md`에 문서화됐다. canonical lease record는 `doc_id`, `node_id`, optional `base_url`, `lease_id`, `epoch`, `acquired_at`, `renewed_at`, `expires_at`를 포함하고, stale 판단은 `expires_at` 기준으로만 하도록 고정했다.
- shared SQLite snapshot/lease 조합의 실제 owner handoff는 두 노드 앱을 동시에 띄운 end-to-end 테스트로 검증됐다.
- managed coordination lease service와 shared SQLite snapshot store를 묶은 실제 owner handoff도 두 노드 앱 회귀 테스트로 검증됐다.
- managed coordination lease service와 managed snapshot service를 함께 묶은 실제 owner handoff도 두 노드 앱 회귀 테스트로 검증됐다.
- embedded durability backend 운영 비교 기준은 `README.md`와 `docs/setup.md`에 문서화됐고, 이제 backend별 저장 단위, payload 가시성, 손상/복구 주의점, pure-Rust/no-bindgen/no-native-conflict 기준선 여부까지 backend-by-backend 매트릭스로 바로 비교할 수 있다.
- `dbless`는 redb-backed single-file typed table store라 named table key scan으로 catalog를 복구하기 쉽지만, payload가 typed binary라 운영자가 수동으로 직접 점검하는 용도보다는 file-level backup/restore 절차에 더 적합하다.
- `simple_db`는 line-oriented single-file store라 파일 단위 백업과 payload 점검은 단순하지만, 전체 파일 rewrite 기반이어서 partial rewrite 상황에서는 최근 쓰기 일부가 유실될 수 있다는 점을 운영 기준으로 봐야 한다.
- `docdb`는 auto-dump single-file JSON store라 temp+rename 기반 전체 파일 교체로 쓰기 경계를 단순화하지만, catalog 파일 전체 역직렬화에 의존하므로 손상 시 startup 복구 실패가 전체 store에 번질 수 있다는 점을 운영 기준으로 봐야 한다.
- `shorterdb`는 directory-backed WAL/SST LSM store라 공개 key iterator 없이도 `__catalog__` key로 document set을 고정해 복구 경계를 단순화할 수 있지만, file-level 백업 대신 engine 디렉터리 전체와 catalog key를 함께 다뤄야 한다는 점을 운영 기준으로 봐야 한다.
- `nikidb`는 single-file B+tree bucket store라 file-level backup/restore 절차는 단순하지만, payload와 catalog가 binary bucket file에 함께 저장돼 수동 payload inspection보다는 whole-file backup/restore와 회귀 테스트 기반 검증에 더 적합하다.
- `nodb`는 single-file key-value store라 file-level backup/restore 절차는 단순하지만, dump/rename 뒤 reopen 시 전체 map load에 의존하므로 file corruption 시 startup 복구 실패가 전체 store에 번질 수 있다는 점을 운영 기준으로 봐야 한다.
- `persistent_kv`는 directory-backed WAL/snapshot set store라 process-crash durability와 key scan 복구 경계는 단순하지만, file-level 교체보다는 snapshot 디렉터리 전체 백업/restore와 회귀 테스트 기반 검증에 더 적합하다.
- `saberdb`는 single-file pretty JSON store라 atomic temp+rename 경계와 파일 단위 backup/restore 절차는 단순하지만, whole-file map rewrite와 전체 역직렬화에 의존하므로 file corruption 시 startup 복구 실패가 전체 store에 번질 수 있다는 점을 운영 기준으로 봐야 한다.
- `jsondb`는 schema-versioned pretty JSON store라 top-level version metadata와 atomic temp+rename 경계는 단순하지만, write guard drop마다 whole-file pretty JSON rewrite와 전체 역직렬화에 의존하므로 file corruption 시 startup 복구 실패가 전체 store에 번질 수 있다는 점을 운영 기준으로 봐야 한다.
- 다음 작업 후보는 같은 제약(pure-Rust/no-bindgen/no-native-conflict)을 만족하는 additional durability backend를 한 건 더 재선정하는 것이다.
- 방금 시도한 후보 중 `grebedb`는 기존 `s3` 경로가 끌어오는 `zstd-sys`와 links conflict로 차단됐고, `unqlite`는 local toolchain에 `libclang`이 없어 build script bindgen 단계에서 차단됐다.
- `bitcasky`는 upstream `Bitcasky::open()` 초기화 경로가 directory lock 파일을 열 때 read/write/append 플래그 없이 `open()`을 호출해 `must specify at least one of read, write, or append access`로 실패하므로 이번 후보에서는 제외했다.
- sandboxed run에서는 commit/push/WebSocket 통합 테스트가 계속 차단될 수 있다. 현재 스크립트와 운영 규칙은 이 차단을 없애는 것이 아니라 조기에 탐지하고 unrestricted 실행으로 분리하는 용도다.
